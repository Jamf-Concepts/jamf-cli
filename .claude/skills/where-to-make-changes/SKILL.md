# Where to Make Changes

|---|---|

| Change what is redacted from a `-vvv` body log | `RedactCredentialBody` (`internal/client/client.go`) — JSON, form-encoded and Classic XML; `redactBodyForLog` composes it with `RedactTokenBody` and every body log goes through it |
| Change behavior of all modern API commands | `generator/parser/generator.go` (`resourceTemplate`) |
| Change behavior of all classic API commands | `generator/classic/generator.go` (`classicResourceTemplate`) |
| Change how OpenAPI specs are parsed | `generator/parser/parser.go` |
| Change singleton detection logic | `generator/parser/parser.go` → `detectSingleton()` |
| Change which schemas `detectNameField` may answer from | `representationSchemas` (`generator/parser/monolithparse.go`) — the per-resource `$ref` closure minus every `x-action` payload, because an action's body is a command and its fields are arguments. One components map means the closure reaches the shared `ExportField{fieldName}` body of every `/export` action, which cost `/v1/packages` and `/v2/jamf-remote-assist/session` their name field. `detectIDField` keeps the full closure |
| Change which side of a no-param GET collision keeps `get`/`list` | `isResourceRootPath` (`generator/parser/parser.go`), read against the `Resource.Root` the grouping derived — **not** against a root inferred from the colliding paths, which got three cases wrong (see `TestNoParamRootKeepsThePlainVerb`). A resource with no root endpoint keeps terminal-segment naming throughout (`pro ldap` has `groups`/`servers`/`ldap-servers` and no `list`, there being no `GET /v1/ldap`) |
| Change what makes a sub-path a nested command of its own | `subResourceWriteMethods` / `subResourceRoots` (`generator/parser/subresource.go`) — a sub-path carrying `PUT`/`PATCH`/`DELETE` **on the sub-path itself** is a separately-writable object, so `pro sso-settings cert delete` rather than `pro sso-settings delete` deleting the certificate. Derived, no override table; `TestSubResourcePartitionIsPinned` pins the 9 it admits and the composition of what it refuses |
| Rename a lone no-param GET that kept `list` on a non-collection path | `renameLoneNonCanonicalList` (`generator/parser/parser.go`) — **scoped to a resource the sub-resource split touched**, deliberately: six unrelated resources have the same shape (`pro m2m list` returns a tenant id, `pro jamf-protect list` the Protect plans) and renaming those is seven breaking renames this change is not |
| Change which tag names a resource whose root carries two | `groupTag` (`generator/parser/taggroup.go`) — the tag of the group's **own root collection**, then the most frequent tag. Eight roots in the 11.31.1 monolith hold two tags, which is the correct grouping; last-write-wins over sorted paths named three of them wrongly, shipping the `/v1/users` CRUD as `pro smart-user-groups` with an `apply` that deleted and recreated a **user record**. `TestMergedTagGroupsAreNamedByTheirRootCollection` is the guard |
| Change what happens when a path's methods disagree on their tag | `soleBaseTagOf` (`generator/parser/monolithparse.go`) — refused, naming the path and both tags. The tag bounds what may be grouped and a path joins exactly one group, so nothing downstream can express a path carrying two; taking the first was silent, and `TestParseMonolith_LosesNoEndpoint` counts endpoints rather than checking where they went. Zero live paths disagree, so it refuses nothing today |
| Change how an untagged path is bounded | `boundKey` (`generator/parser/taggroup.go`) — by its own root, not by the empty tag it shares with every other untagged path. Pooling them hands `resolveRootsWithinBound`'s no-survivor fallback a set of unrelated roots and folds them all into the largest: `/v1/health-check` and `/v1/health-status` would come out as one resource. No live path is untagged; `TestPathRootRule_TopLevelCollectionIsAlwaysARoot` is the guard |
| Point a retired `<resource> <verb>` invocation at where the operation went | `movedInvocations` (`internal/commands/moved_invocations.go`) — keyed on the command path **after** resource-alias resolution, so one entry covers every spelling. A resource alias resolves the first token only, so cobra answered the other 43 with `unknown command`, indistinguishable from a typo on the class that is hardest to self-diagnose |
| Change what a former leaf that became a command group answers | `formerLeafGroups` (`internal/commands/moved_invocations.go`) and `guardFormerLeafGroups` (wired in `root.go` **after** `guardUnknownSubcommands`, whose RunE it wraps) — a data request (`--output`, `--field`, `--select`, `--out-file`) is refused naming the leaf; a bare invocation and a typo are unchanged. `pro csas token -o json` used to pipe cobra's help text into `jq` at exit 0 |
| Change which of two colliding operations keeps a plain verb | `qualifyDuplicateVerbsOutsideTheRoot` (`generator/parser/parser.go`), run last in `buildResourceShell` — the resource's own root or root/`{id}` keeps `create`/`update`/`delete` and the loser is qualified by the last non-param segment of its own path (`ldap-create`, `dashboard-delete`). It touches writes only: a colliding GET is left to `dedupeOperations`, whose collection-path preference is what `resourceGetDetailPathOverrides` depends on. Before it, `dedupeOperations` **deleted** the loser with a warning and exit 0, which cost `pro enrollment-customization` its own `create`, `update` and `delete` and pointed its `apply` at an LDAP panel path |
| Separate two methods on the same path whose derived names collide | the fallback in `disambiguateSameTerminalOps` (`generator/parser/parser.go`) — `methodVerbPrefix` when the path-derived name is already taken by a sibling on the *same* path, which is what `buildDisambiguatedName` cannot express. Three methods on `/v2/computer-prestages/{id}/scope` all reduced to `scope-by-id` and two were dropped |
| Decide which of two colliding sub-path operations keeps a plain verb when **neither** addresses the root | `disambiguateSameTerminalOps` (`generator/parser/parser.go`), which now takes the resource root — when no member of the collision group is the resource's own collection or item, none has a claim on the plain verb and each is qualified by `owningNoun`. That helper returns "" for a *parameter*, which is what keeps `pro certificate-authority der`/`der-by-id` (`active/der` vs `{id}/der` — an item selector, not a noun) off the rule, and version-strips both sides, a `PathGroup` root keeping a leading `preview` where `stripVersionSegments` drops it |
| Stop an API version leaking into a command name | `buildDisambiguatedName` (`generator/parser/parser.go`) skips a version segment. Two paths differing *only* in version are folded by `deduplicateVersionedOps` long before, so a version segment here always sits beside a real difference. Three names carried one (`v-4-computers-inventory-erase`, `v-2-scope-delete-multiple`); `TestNoCommandNameCarriesAnAPIVersion` is the guard |
| Refuse to ingest a path at all | `droppedPaths` / `droppedTags` (`generator/parser/pathgroup.go`), read by `KeepPath`. Reach for a path when the endpoint is superseded at a *different path shape* — `deduplicateVersionedOps` keys on the shape, so it keeps both and the withdrawn one takes the plain verb (inventory-preload v1; `/v1/computer-inventory/{id}/erase`, where v4 spells the collection segment plurally). `droppedByPolicy` in `monolithparse_test.go` has to name it too |
| Change what a destructive command's confirmation, dry-run or bulk request says or sends | `actionMethod` / `actionPhrase` / `actionPhraseTitle` / `actionPhrasePast` / `actionNoun` in the `resourceTemplate` FuncMap (`generator/parser/generator.go`). The destructive bulk and confirmation blocks are shared by a plain `DELETE` and by a destructive `x-action`, and used to hardcode both: `pro mobile-device-groups erase --from-file` sent `DELETE` to a POST-only path and reported "Deleted", and the group prompt offered to "delete N computer-inventory" for a fleet wipe. An action quotes its own name rather than being conjugated |
| Make a duplicate command registration fail instead of shipping a resource twice | `CheckRegistryCollisions` — `generator/parser/generator.go` for the modern generator, `generator/classic/generator.go` for Classic. Called from each `GenerateRegistry` *and* ahead of `main.go`'s per-resource write loop, because a shared file name means the second `Generate` overwrites the first and the resource is already gone by the time the registry is emitted. Both symptoms are silent: a repeated `root.AddCommand(NewXCmd(ctx))` compiles, so the resource ships twice in `pro --help` and cobra resolves every path beneath it to the first copy, and `make verify-generated` reproduces the duplicate faithfully so the tree reads as up to date (#362). It refuses rather than collapsing the repeat — two resources deriving one identity means the grouping upstream is wrong |
| Make a stale `pro.go` wiring key fail instead of shipping an extra command | `findWiringParent` / `recordStaleProWiring` (`internal/commands/pro.go`), asserted by `TestProWiringResolvesEveryNameItUses`. All three helpers key on names the generator derives, and a stale key used to be a silent no-op — which for `removeSubcommand` leaves the generated command in place and for `replaceSubcommand` adds the replacement beside it. The child half was unguarded, and that is the half that ships a second destructive command |
| Change how the typed resource token is read for the deprecation warning or the moved-verb refusal | `resourceTokenAfter` / `visibleFlags` (`internal/commands/deprecated_names.go`) — flags are stripped by cobra's own rules, asking the assembled flag set whether one consumes the next argument. Assemble the set: `cmd.Flags()` holds only the command's *own* flags until cobra's unexported merge has run, so a root persistent flag looks unrecognised and eats the token |
